一、 產品客服 Agent 初步構想（核心定義與定位）
1. 產品定位與命名
產品名稱：popAI—— 智慧追星日常與演場會專屬客服助理。
目標受眾：K-pop / 流行音樂粉絲、常態性跨國追星與演唱會觀演族群。
核心價值：將分散在社群平台與官方網站的碎片化情報集中化，以對話式介面提供即時問答、時區轉換與購票指引，降低粉絲的資訊搜尋成本與交易風險。
2. 學習思路與知識結構拆解
依據「應用場景 ➔ 核心名詞 ➔ 知識結構」梳理 Agent 的運作輪廓：
核心名詞定義：
客服 Agent（Customer Service Agent）：能理解用戶自然語言提問，主動過濾關鍵資訊並給予精準解答的智慧代理人。
知識檢索（Knowledge Base）：將官方行程表、售票規章、場館座位圖結構化，作為 Agent 正確回答的依據。

第二層：理解層
意圖識別與實體抽取器
1. 意圖分類：將問題精準分流為「同款踩點」、「跨國日程」、「演出票務」、「二手行情」四大支線。
2. 參數提取：抽離藝人成員、城市地點、節目時段、場館區域、商品版本與價格等關鍵詞。

第三層：調度層
專屬知識庫與工具調用 (RAG & Tools)
依據意圖調度專業資源：
• 支線 1（同款踩點）：檢索「聖地巡禮庫」調出 Vlog/公開行程之店名、同款菜單、座位標記，並透過「地圖工具」串聯順路動線與公休提醒。
• 支線 2（時差日程）：調用「時區換算運算器」將 KST/EST 精確換算為台灣時間，比對當日官方行事曆。
• 支線 3（演出票務）：檢索「售票規則規章庫」與「場館視角庫（Stage-View）」提供實名制與座位視野建議。
• 支線 4（二手行情）：比對「歷史成交均價庫」與「詐騙手法特徵庫」。

第四層：防禦層
安全合規與防詐邊界防護
1. 隱私與踩點安全約束：僅提供官方公開之商業店家或拍攝地，嚴禁檢索或提供私人非公開住址與私生活行程。
2. 金流與交易防詐預警：涉及門票讓讓或周邊轉賣，強制注入官方正規管道與反詐騙警語。
3. 資訊時效檢核：若店家已歇業或巡演為未證實傳聞，主動加上標籤提醒，杜絕 AI 幻覺。

二、 核心使用場景說明（三大業務情境）
場景一：跨國日程查詢與時差即時換算（日常高頻）
使用者痛點：藝人直播、節目播出與線上簽售常以韓國時間（KST）標示，跨國粉絲常因 1 小時時差而錯過即時互動。
Agent 應對行為：用戶詢問「今天晚上有直播嗎？」，Agent 檢索日程庫後，自動將 KST 轉換為台灣時間（TST）並清楚列出時程表。

場景二：偶像同款聖地巡禮與打卡動線指南（休閒旅遊） 
使用者痛點：偶像在 Vlog、SNS 或綜藝中造訪的餐廳與景點資訊零碎，粉絲自行爬文常找不到精確店名、韓文地址、營業公休日，到了現場也往往不知道偶像所坐的同款座位或點過的餐點。
Agent 應對行為：用戶提供地點或偶像名稱，Agent 檢索「聖地巡禮知識庫」，輸出中韓對照店名、地圖導航連結、同款餐點推薦與座位標記，並串聯周邊鄰近打卡點規劃順路動線，同時主動核對最新營業狀態以防撲空。

場景三：演唱會搶票規則與觀演指南（演出檔期）
使用者痛點：各大售票系統（如拓元、KKTIX）的實名制認證條件、會員先行抽選時程各不相同，粉絲常因不熟悉規則而喪失資格。
Agent 應對行為：用戶詢問購票須知時，Agent 列出該場次的開賣時程、會員認證步驟、退票手續費階梯與場館基本視角注意事項。

場景四：二手周邊行情與防詐 
使用者痛點：社群平台（如 Threads、X、FB 社團）上的小卡與周邊交易市場水深且價格混亂，新手容易遭遇惡意炒價、假卡盜印，甚至面臨假買家、假客服連結與私下匯款等釣魚詐騙。
Agent 應對行為：用戶詢問小卡價格或貼上交易對話時，Agent 調用「歷史成交行情庫」提供合理的市價區間參考；若檢測到「簽署金流保障協議」、「要求先行匯款」等高風險字眼，即刻觸發防禦機制，輸出防詐預警並引導使用具備保障的第三方交易管道。
