一、 本次學習目標
依照課綱單元 0 的實踐與檢核標準，建立 GitHub Repo 並上傳 README，說明 AI Agent 的初步構想與使用場景。雖然之前做過一遍單元0，但主題被老師拒絕，所以依據老師的建議與要求，本專案預計使用 Coze 平台製作「智慧產品客服 AI 助理」，希望讓 Agent 不只是單純被動回答問題的聊天機器人，而是能完整串聯「產品手冊查詢（Knowledge）」、「購物車暫存（Memory）」、「付款後寄信通知（Plugin）」以及「言論安全過濾（Guardrail）」等核心元件，具備實際處理電商客服流。
二、 專題製作動機
我目前是一名大二的學生，平時經常在各類網購平台或品牌官網消費，發現許多中小型電商或個人賣家雖然有設置客服聊天機器人，但體驗往往不夠完善：
很多傳統機器人只會機械化地比對關鍵字，常常回答非所問；如果詢問具體的產品規格（例如耳機是否防水、保固幾年），AI 甚至可能產生不符合官方資料的錯誤幻覺。


當我們在對話中說「我想買這個商品」時，一般的機器人缺乏記憶功能，無法直接在對話裡幫忙暫存品項，只能丟出外部連結讓客人自己找。
 
顧客回報轉帳付款後，通常需要賣家以人工方式去核對並手動發信通知，無法在對話中直接完成動作閉環。
老師在課堂上也提醒我們，做 AI Agent 必須搞懂它的技術本質，避開缺乏數據或自己不會用的虛假需求。因此，我想從基礎的「電商產品客服」出發，設計一個名為「NovaGear 智慧生活選物客服助理」的 Agent，讓它能夠精確讀取模擬的產品資料、記住顧客想買的品項，並在確認付款後自動調用外部工具寄送信件，成為一個真正能輔助賣家的實用工具。
三、 我希望它可以解決什麼問題？
產品規格資訊分散且容易有 AI 幻覺： 顧客詢問防水等級、保固條款等細節時，客服機器人如果沒有依據官方資料回答容易出錯。透過引入知識庫（Knowledge），讓 Agent 嚴格依據產品手冊作答。
 
對話缺乏上下文記憶（缺乏購物車狀態維護）： 一般對話模型聊完就忘，無法在同一次對話中記住顧客「想要購買」哪些規格與配件。希望透過記憶機制（Memory），將品項暫存在工作記憶變數中。
 
對話無法產生實際行動（缺乏外部閉環）： 純語言模型無法真正與外部世界互動。當顧客回報付款完成時，希望透過串接外部外掛（Plugin），自動將購買明細與確認通知發送至顧客信箱。
 
面臨惡意測試或爭議言論缺乏保護： 若顧客誘導詢問「競品是不是很爛」或要求「非官方的超低折扣」，容易引發品牌公關問題。需要透過安全護欄（Guardrail）阻擋不該說的違規與不實言論。 
 
四、 預想的初步功能
大腦與 Prompt 規範（LLM & Prompt）：在 Coze 設定合適的語言模型，撰寫結構化的 System Prompt 定義客服助理的角色、親切語氣與行為規範。
 
產品手冊與政策查詢（Knowledge）：模擬一份《NovaGear 產品與服務指南》，讓 Agent 能精準讀取藍牙耳機、磁吸行動電源等規格與 7 天鑑賞期條款，避免幻覺。
 
購物車狀態記憶（Memory）：當顧客在對話中說出購買意圖與品項時，Agent 會將品項與金額暫存入購物車記憶變數中。
 
付款完成郵件通知（Plugin）：當顧客確認已付款並提供 Email 時，Agent 能觸發外部發信外掛，自動寄出訂單確認信件。
 
安全邊界防護（Guardrail）：設定限制邊界，阻擋惡意 Prompt 注入，遇到評估競品或非授權折扣時給予標準拒絕回應。

七、 目前遇到的問題與下一步
目前比較需要釐清的是如何在 Coze 平台上將五個元件實際配置並串聯起來：
一開始容易覺得「客服機器人」只要在 Prompt 裡寫好角色就好，但深入規劃後發現，如果要讓它記住購物車（Memory），需要學習如何在 Coze 裡設定工作變數（Variable）或資料表，才不會在對話幾輪之後遺失資訊。


在付款後要發送通知信（Plugin），需要了解如何選用合適的外掛工具與 API 參數傳遞，讓 Agent 能夠辨識顧客提供的 Email 並正確發出通知。
 
目前預計先從最基礎的設定開始，配合接下來的單元進度，依序完成：
第一步（單元 1）：在 Coze 平台建立 Agent，完成 LLM 選型、觀察不同模型的成本與精準度差異，並配置基礎 Prompt。


後續步驟：逐步掛載產品手冊知識庫（Knowledge）、設定購物車變數（Memory）、串接發信外掛（Plugin）與設置防護規則（Guardrail）。
